## Shell runtime bug 修复：msg.content 为数组时 .trim() 崩溃

### 问题
`Chat.js:200` `rawContent.trim is not a function` — msg.content 可能为 OpenAI 富文本数组格式（`[{type:'text', text:'...'}]`），直接调用 `.trim()` 崩溃。

### 修复
- **Chat.js**: 新增 `extractText(content)` 辅助函数，统一处理 string/array/null 三种类型
  - string → 直接返回
  - array → 过滤 `type:'text'`，拼接 `.text`
  - 其他 → `String(content)`
  - 暴露为 `window.extractText` 供其他模块使用
- 4 处使用 `msg.content || ''` 的地方改为 `extractText(msg.content)`
- 2 处使用 `msg.reasoning_content.trim()` 的地方改为 `extractText(msg.reasoning_content).trim()`
- **ChatEventHandler.js**: `_handleMessageUpdated` 中 `message.content` 和 `message.reasoning_content` 也通过 `extractText` 转为字符串

### 期间修复的 kernel 构建问题
- OpenRouterService.ts: `export { OpenRouterService };` 被错误放在 class 体内 → 移到文件末尾（class 声明用 `export default class` + 文件末尾 `export { ... }` 双重导出）
- LMStudioService.ts: 之前误删 `export default LMStudioService;` → 恢复，并补 `export { LMStudioService };`
- IProviderAPIService.ts: 之前误删 `export default IProviderAPIService;` → 恢复

## 修复 ChatProgram 缺失 MESSAGE_ADDED 事件导致 ChatPage 无法渲染消息 role

### 问题
ChatPage 监听 `MESSAGE_ADDED` / `MESSAGE_DELETED` / `CURRENT_SESSION_CHANGED` 来触发 `render()`（全量渲染），但 ChatProgram 只发出了 `STREAM_*`、`MESSAGE_DELETED`、`ACTIVITY_STATE_CHANGED`——**从未发出 MESSAGE_ADDED 和 CURRENT_SESSION_CHANGED**。

结果：
- IPC 路径（ChatEventHandler）能工作：它通过 `_updateMessageContent(messageId, content)` 直接更新已有 DOM 元素的内容，不需要读 role
- ChatPage 路径不工作：新消息加入了 session 但没人触发 render()，MessageBubble 根本没被调用，role 无法读取和渲染

### 修复（ChatProgram.ts）
- `sendMessage()` 中 `sm.addMessage(userMsg)` 后：发出 `MESSAGE_ADDED`
- `sendMessage()` 中 `sm.addMessage(assistantMsg)` 后：发出 `MESSAGE_ADDED`
- `_executeToolCalls()` 中 `sm.addMessage(toolMsg)` 后：发出 `MESSAGE_ADDED`
- `sendMessage()` 中 `sm.createSession()` 创建新 session 后：发出 `CURRENT_SESSION_CHANGED`

### 验证
- 构建 58.35 kB，17 测试全部通过
