- 4 处使用 `msg.content || ''` 的地方改为 `extractText(msg.content)`

## 修复 sidepanel.html：ES module 文件被当普通 script 加载

### 问题
扩展加载报 20+ 个 `Unexpected token 'export'` / `Cannot use import statement outside a module`。原因是 Shell JS 文件已改为 ES module 语法（import/export），但 HTML 仍用普通 `<script>` 标签逐个加载。

### 根因
ES module 迁移后，所有 Shell JS 文件通过 import 链串在一起，Vite 从 `app.js` 入口打包成一个 `dist/sidepanel.bundle.js`。但 HTML 仍然引用旧 IIFE bundle (`kernel.bundle.iife.js`) 并逐个加载全部原始 JS 文件，导致浏览器按普通 script 解析含 import/export 的代码。

### 修复
sidepanel.html 精简为 3 层：
1. `error-handler.js` — 全局错误捕获（普通 script，最先加载）
2. 第三方库（codemirror + marked）— 普通 script，设置 window 全局
3. `dist/sidepanel.bundle.js` — Vite 打包的 ES module（`type="module"`，延迟执行）

移除了全部 20+ 个独立 app script 标签（toast/confirm/dom/time/UI/Chat/各 page/event-handler/tool/service/events/app.js 以及旧 IIFE bundle）。

### 验证
- `npm run build` 通过，58 模块，133.87 kB
- bundle 内含 ChatEventHandler/navigateTo/Toast/getKernel 等关键符号
- ScriptInjector.js 从 HTML 移除（已被 ScriptInjector.module.js 替代，后者由 background.js 使用）

## UI 设计：基于 Preact + Signals 的 Shell 高保真稿

用户确认采用 **B 方案（Preact + TypeScript + Signals）** 作为 Shell 层现代化架构，要求输出完整 UI 稿。

### 过程
- 尝试用 Ardot 画布输出设计稿，但 Ardot MCP adapter 多次连接失败（`NO_ADAPTER`），无法继续画布操作。
- 改为交付自包含的 HTML 高保真原型，作为可直接预览和后续转 Preact 组件的参考。

### 交付物
- `web-agent-client-ui-mockup.html`：440×760 四屏并列展示
  - **Chat**：侧栏 + 消息流（用户/助手气泡）+ 流式光标 + Tool Call 卡片（Running/Done 状态）+ 底部 Composer
  - **History**：会话列表（Today / Yesterday 分组）
  - **Scripts**：脚本卡片网格 + 代码预览
  - **Settings**：Provider 标签页（OpenAI / OpenRouter / LM Studio）+ API Key / Base URL / Model / Temperature 等表单

### 设计系统
- 深色主题（#1A1A1A 背景、#242424 卡片、#FFFFFF 主文字）
- 强调色：荧光绿 #9EFF00（CTA、active nav、badges）
- 字体：Inter + JetBrains Mono
- 8px 圆角、1px 细边框、无阴影的扁平工程风
- 侧栏 56px 图标-only，符合 Chrome Side Panel 的紧凑空间
