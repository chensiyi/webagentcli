## Kernel 设计审查

完成了对当前 Kernel 架构的全面审查，输出了设计审查文档 `docs/kernel-design-review.md`。

核心发现：
- 当前架构是 OS 隐喻驱动（service registry / IPC / syscalls / capabilities / bootloader），但 Agent 需要的是"注意力/记忆/工具"三支柱
- **死基础设施**：CapabilityManager（从未接入工具执行路径）、ProcessManager（只有 create/get/remove 空壳）、getContextWindow（返回空数组）、IPC 的优先级/request/response/统计（从未使用）
- **关键缺失**：无 system prompt 组装、无上下文窗口管理、无记忆/知识层、LLM 无自我感知能力、无动态工具注册
- ChatProgram 是上帝类，承担 6 项职责

提议的改动方向：
1. 新建 ContextEngine（system prompt + 上下文管理）
2. 新建 MemoryManager（跨会话知识存储）
3. 4+1 最小工具链：browser_exec + memory_op + task_op + context_inspect + tool_register
4. 激活或删除 ProcessManager/CapabilityManager
5. 精简 IPC 和 Bootloader

## Kernel Phase 3 清理：IPC 精简 + Bootloader 简化 + ProcessManager 看门狗实现

### 1. IPC 精简（kernel/IPC.ts）
- **移除**：PRIORITY/PRIORITY_NAMES 常量、emitHigh/emitLow、request/onRequest/respond/respondError、stats 统计、getStats()、messageHistory/getHistory/clearHistory/maxHistory
- **保留**：on/off/once/emit/use(中间件)/getOrCreateChannel/getRegisteredEvents/getListenerCount/removeAllListeners/destroy
- **IPCMessage 简化**：移除 priority/priorityName 字段，保留 event/data/timestamp/id/origin
- **emit 签名简化**：从 `emit(event, data, options)` → `emit(event, data)`
- app.js 和 src/main.ts 的 IPC 中间件日志已同步更新（移除 priorityName 引用）

### 2. Bootloader 8→4 阶段（kernel/Bootloader.ts）
- 旧 8 阶段：CORE_INIT → SERVICES_REGISTER → SERVICES_INIT → TOOLS_REGISTER → HANDLERS_INIT → CONFIG_LOAD → UI_RENDER → READY
- 新 4 阶段：**INIT → REGISTER → START → READY**
  - INIT = 原 CORE_INIT（IPC 就绪）
  - REGISTER = 原 SERVICES_REGISTER（注册服务工厂）
  - START = 合并原 SERVICES_INIT + TOOLS_REGISTER + HANDLERS_INIT + CONFIG_LOAD（初始化服务 + 注册工具 + 创建 Programs + 加载配置）
  - READY = 原 READY
- app.js 和 src/main.ts 的 Bootloader hooks 已同步更新

### 3. Process 模型升级（kernel/models/Process.ts）
- 完整生命周期状态机：created → running → paused → completed / failed / cancelling → cancelled / killed
- VALID_TRANSITIONS 校验非法状态流转
- 新增字段：startedAt/endedAt/error/timeout/terminateFn/watchdogTimer
- 方法：start/complete/fail/pause/resume/beginCancel/finishCancel/forceKill/setWatchdog/clearWatchdog/setTerminateFn
- _forceStatus() 跳过校验（仅用于看门狗强制终止）
- isFinished()/isActive() 查询方法

### 4. ProcessManager 看门狗实现（kernel/services/ProcessManager.ts）
- **init(kernel)**：由 Kernel.boot() 自动调用，注册 IPC task:cancelRequest 监听
- **create(name, options)**：创建进程，支持注入 terminateFn 和 timeout
- **cancel(id, reason)** 看门狗核心流程：
  1. 状态 → cancelling
  2. 启动 setTimeout 看门狗定时器（默认 10s）
  3. await terminateFn()（优雅终止）
  4a. 成功 → 清除定时器 → 状态 → cancelled
  4b. 超时 → 看门狗触发 _forceKill → 状态 → killed
- **_forceKill(id, reason)**：强制终止，_forceStatus('killed')
- **shutdown()**：Kernel.shutdown() 自动调用，并发 cancel 所有活跃进程，仍未终止的 forceKill
- **cleanup(maxAge)**：清理已完成进程（默认 5 分钟后）
- IPC 事件：通过 task channel 发送 CREATED/STARTED/COMPLETED/CANCELLED/FORCE_KILLED/STATUS_CHANGED/ERROR/DELETED
- KernelRef 最小接口避免循环依赖（同 ScriptsManager/ProviderFactory 模式）

### 5. Events.ts 更新
- TASK 新增：CANCEL_REQUEST ('task:cancelRequest')、FORCE_KILLED ('task:forceKilled')
- IPC 移除：REQUEST_TIMEOUT
